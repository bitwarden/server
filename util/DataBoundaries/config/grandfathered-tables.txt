# Table files that predate the product-ownership rule and are exempt from it, because
# CODEOWNERS resolves everything directly in src/Sql/dbo/Tables to the database platform
# team rather than to a product team.
#
# This list may shrink and must never grow. To remove a line, move the table file to
# src/Sql/dbo/<Domain>/Tables/ so the owning team resolves from CODEOWNERS, then delete
# its entry here. Adding a line is a policy violation that "check --sql-ownership" fails.
#
# The list covers three groups. Only the first is unclassified; the other two are domain
# folders whose ownership resolves to the database platform team for reasons that are
# decisions rather than accidents, so they cannot be fixed by moving a file:
#
#   1. The unclassified root src/Sql/dbo/Tables/. This is the group the ratchet is aimed
#      at, and moving a file into a domain folder is the whole ownership change.
#   2. src/Sql/dbo/Pam/Tables/. The commented CODEOWNERS rule
#      "src/Sql/dbo/Pam @bitwarden/dept-dbops" keeps PAM schema with DBOps deliberately,
#      so removing these entries requires that decision to change first.
#   3. src/Sql/dbo/SecretsManager/Tables/. No Secrets Manager CODEOWNERS rule exists and
#      no team handle exists to point at, so these are blocked on a decision rather than
#      on work. Do not invent a handle: a rule naming a team that does not exist matches
#      nothing while looking correct.
